# Лист — блог на PHP 8.5

MVC-блог без фреймворков: **PHP 8.5, MySQL 8.4, Smarty 5.8.4, PDO и SCSS**.

## Запуск

Нужны Docker и Docker Compose v2. Из корня проекта:

```bash
cp .env.example .env
docker compose up -d --build
```

Демонстрационные пароли из `.env.example` предназначены только для локального запуска.

## Функциональность и правила

**Главная:** каждая категория с опубликованными статьями и до трёх её последних материалов; ссылка «Все статьи». Для выборки используется один запрос с `ROW_NUMBER()` и группировкой по категории, без запроса на каждую категорию. Навигация получает категории одним отдельным запросом.

**Категория:** название, описание, шесть статей на страницу, сортировка `date` или `views`, ссылки пагинации с сохранением сортировки. Смена сортировки ведёт на первую страницу. При совпадении дат/просмотров порядок уточняется по ID.

**Статья:** обложка, заголовок, описание, полный текст, дата, категории, просмотры и до трёх похожих материалов. Похожие имеют хотя бы одну общую категорию, упорядочены по дате, не включают текущую статью и не дублируются при нескольких общих категориях. Если найдено меньше трёх, показываются найденные.

**Публикация:** `published_at <=` единому UTC-времени начала обработки запроса. Будущие статьи скрыты во всех выборках, включая прямой переход по ID.

**Просмотры:** один успешный GET страницы статьи — одно увеличение через атомарный `UPDATE views = views + 1`. Повторные посещения считаются. HEAD, главная, страницы категорий и неуспешный рендеринг не увеличивают счётчик. Это не уникальные просмотры.

**Ошибки:** неизвестная категория/статья/страница — 404; некорректный `page` или `sort` — 400; неподдерживаемый метод известного маршрута — 405 с `Allow: GET, HEAD`. Пустая существующая категория — обычная страница 200.

## Данные и безопасность

Три таблицы: `categories`, `articles`, `article_category`. В связующей таблице составной первичный ключ и внешние ключи с каскадным удалением связей; обратный индекс поддерживает выборки по категории. Назначение хотя бы одной категории обеспечено сидером; сам внешний ключ не запрещает статью без связей.

В модели статей есть отдельные методы для главной, пагинации, поиска опубликованной статьи, счётчика и похожих. Для похожих используется `EXISTS`, а не соединение, создающее повторы карточек.

PDO работает с native prepared statements. Значения параметризованы, `LIMIT/OFFSET` привязываются как целые числа. `ORDER BY` выбирается только из `ArticleSort`; пользовательская строка не попадает в SQL.

В Smarty включено автоэкранирование. Текст статьи — обычный текст с абзацами, не исполняемый HTML. Обложки локальные; внешние CDN, шрифты и JavaScript для работы сайта не нужны.

Document root — только `public/`, а не корень проекта. Smarty-компиляция, конфигурация и CLI находятся вне него. Ответы содержат CSP, `nosniff` и `Cache-Control: no-store`. Технические ошибки пишутся в лог; резервная HTML-страница 500 не зависит от Composer, MySQL или Smarty. Сессии и cookie сессии не используются.

## Сидинг

Демо-набор: **5 категорий, 32 опубликованные статьи и 1 запланированная**. Четыре категории содержат достаточно статей для пагинации; «Заметки» пустая. Есть статьи с несколькими категориями, разные просмотры и совпадающие даты. Даты рассчитываются относительно запуска сидера.

```bash
docker compose exec app php bin/init-db.php
docker compose exec app php bin/seed.php
```

Обычный сидинг пропускается, если категории или статьи уже существуют. Предполагается один одновременно запущенный сидер.

**Команда ниже удаляет все статьи, категории и связи и создаёт демо-набор заново:**

```bash
docker compose exec app php bin/seed.php --reset
```

Тестовый сервис выполняет:

```text
php bin/lint.php             Синтаксис PHP-файлов
```

## SCSS

```bash
bun install
bun run watch
# Однократная сборка:
bun run build
```

SCSS — `resources/scss/app.scss`, готовый CSS — `public/assets/app.css`. При Docker-сборке CSS собирается отдельным Node-этапом; Node не входит в PHP runtime.

Sass закреплён в `package.json`; npm lock-файла нет. Docker-образы закреплены по веткам, а не digest, поэтому будущие сборки не обязаны быть побайтово идентичны.

Исходники копируются в Docker-образ, bind mount кода нет. После изменения кода пересоберите сервисы:

```bash
docker compose up -d --build
```

## Без Docker

Нужны PHP **8.5** с `pdo_mysql`, `mbstring`, `iconv`, Composer 2 и MySQL **8.4**. Создайте БД и локального пользователя с правами на неё, затем:

```bash
composer install
cp config.local.php.example config.local.php
# Укажите в config.local.php настройки созданной БД.
php bin/init-db.php
php bin/seed.php
php -S 127.0.0.1:8080 -t public router.php
```

`.env` читает Docker Compose, не само приложение. Без Docker используются настоящие переменные окружения или `config.local.php`. Локальный конфиг имеет приоритет, в том числе при запуске тестов; не оставляйте в нём переопределение на основную БД для тестового запуска.

Процесс PHP должен иметь право записи в `storage/smarty/compile` и `storage/smarty/cache`. Не используйте `chmod 777`; настройте владельца/группу под своего PHP-пользователя. Встроенный PHP-сервер предназначен для разработки.
